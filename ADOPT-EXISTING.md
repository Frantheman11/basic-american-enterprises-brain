# Add the foundation to an existing brain

Use this path if you have already installed a brain or started saving knowledge.

Open your existing brain in Claude Code. Keep this extracted starter in a separate folder and grant access to it only as needed. Use this prompt:

> Compare my existing brain with the clean foundation folder I select. Keep my facts, raw files, memory, existing skills and setup records. Prepare a list of missing foundation guidance and a proposed diff for conflicts. Add compatible missing files. Ask me to resolve changes to my existing rules or conflicting skills. Verify the result and record which foundation version was adopted.

1. Identify the actual existing brain root and its backup. Review uncommitted work. Make a recoverable copy or local commit before merges; keep this backup private.
2. Compare filenames and purpose. Add missing foundation guidance and blank library templates. Do not replace `config/business.json`, `memory/`, `raw/`, `wiki/`, `todo.md` or setup progress with starter versions.
3. Merge relevant rules into the existing `CLAUDE.md`. Preserve ownership and authority rules. Keep one instruction for each decision; resolve contradictions with the owner.
4. Compare skills with the same name. Preserve client-specific improvements. Add references to shared guidance, then test the merged behavior with a harmless example.
5. Inspect proposed scripts before replacing any existing helper. Check compatibility with the existing setup schema. A starter's factory check is not an upgrade proof for a customized brain.
6. Rebuild applicable indexes and run the existing brain's checks as well as compatible foundation checks. Record failures honestly; do not reset progress to hide them.
7. Record `foundation_version: 1.0.0`, the date, changed files and checks in a dated memory note. Keep task follow-ups in the existing task system.

The ZIP is a reference for a reviewed merge. It is not an automatic upgrade or a reason to restart a working brain.
