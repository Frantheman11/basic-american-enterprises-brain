# Extend the foundation

Read `knowledge/growth-rules.md`, `knowledge/architecture.md`, `library/SKILLS.md` and `tools/README.md`.

State the concrete job and expected result. Search for an existing skill, script or process that owns it. Choose a fact page, process, skill, script, asset or integration according to the actual need. Keep business-specific configuration separate from reusable procedure.

For authorized local changes, implement the smallest useful addition. Use build-skill when a new repeatable procedure is appropriate. For a new external service, identify the required access and prepare the implementation before any activation that needs the owner's authorization.

Keep client operational data in the client's own brain. Add a source/version record for an external dependency. Update callers and the appropriate catalog in the same change. Verify the observable result with a harmless example and record why the structure was chosen.

Do not add schedules, agent teams or infrastructure merely to make the system seem complete.

Rehearse: a new contact fact uses the profile; a repeated workflow uses an existing skill when possible; an actual new integration records its access boundary and verification.
